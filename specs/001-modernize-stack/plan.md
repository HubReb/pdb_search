# Implementation Plan: Modernize the Stack

**Branch**: `001-modernize-stack` | **Date**: 2026-06-20 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-modernize-stack/spec.md`

---

## Summary

Replace the bespoke flat-layout `paper_sorts/` codebase with a modern `src/paper_sorts/` package using SQLAlchemy 2.x + Alembic (persistence), Typer (CLI), pydantic-settings v2 (config), ruff (lint), mypy (types), and pytest + pytest-postgresql (tests). The user-facing CLI behaviour is preserved exactly. Existing personal databases are migrated via a two-revision Alembic chain. Legacy procedural modules are deleted after their functionality is covered.

---

## Technical Context

**Language/Version**: Python ≥ 3.11 (raised from 3.10 per constitution Stack & Constraints)
**Primary Dependencies**: SQLAlchemy 2.x, Alembic, Typer, pydantic-settings v2, pybtex, pylatexenc, cryptography, rich, ruff, mypy, pytest, pytest-postgresql
**Storage**: PostgreSQL only (single user, local). Driver: psycopg v3 (binary).
**Testing**: pytest + pytest-postgresql (host `pg_ctl` at `/usr/bin/pg_ctl`). Session-scoped ephemeral DB.
**Target Platform**: Linux CLI
**Project Type**: CLI tool / personal database
**Performance Goals**: No measurable regression vs. current implementation on same data (constitution Principle IV). Interactive operations only.
**Constraints**: Offline, single-user, no connection pooling beyond SQLAlchemy default, sessions context-managed.
**Scale/Scope**: Personal-library-sized dataset (~hundreds of papers).
