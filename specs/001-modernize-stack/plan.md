# Implementation Plan: Modernize the Stack

**Branch**: `001-modernize-stack` | **Date**: 2026-04-26 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/001-modernize-stack/spec.md`

---

## Summary

Rebuild the `paper_sorts` offline paper-database CLI on mainstream Python frameworks (SQLAlchemy 2.x ORM, Typer CLI, pydantic-settings v2 config, Alembic migrations, ruff lint, pytest + pytest-postgresql test suite, uv package management) while preserving the exact user-facing CLI behaviour (search / add / update / delete / bulk-import). The legacy flat-layout `paper_sorts/` and its procedural modules are replaced by a `src/paper_sorts/` src-layout package with a clean four-layer architecture. An Alembic migration command handles one-shot upgrade of existing personal databases (including both historical schema variants).

---

## Technical Context

**Language/Version**: Python ≥ 3.11  
**Primary Dependencies**: SQLAlchemy 2.x, psycopg v3 (binary), Typer, pydantic-settings v2, Alembic, pybtex, pylatexenc, cryptography (Fernet), rich, pytest, pytest-postgresql, pytest-cov, ruff, mypy  
**Storage**: PostgreSQL (local). Four-table schema: `papers`, `bib`, `authors_id`, `authors_papers`.  
**Testing**: pytest + pytest-postgresql (ephemeral PG from host `pg_ctl`). No mocking of SQLAlchemy session or DB driver.  
**Target Platform**: Linux (developer workstation / offline use).  
**Project Type**: CLI application (personal-use offline tool).  
**Performance Goals**: No measurable regression vs. current baseline on interactive operations (search, add, update, delete) on a personal-library-sized dataset. Benchmark harness at `tests/benchmarks/`.  
**Constraints**: No async, no connection pools beyond SQLAlchemy default, no web surface, no network exposure. Sessions must be deterministically closed (context-managed).  
**Scale/Scope**: Single user, personal library (hundreds of papers).

## Implementation Phases

### Phase A: Infrastructure & Config (T001–T005)
Replace `pyproject.toml` (poetry → uv/hatchling), create `src/paper_sorts/` skeleton, `config.py` with pydantic-settings, `logging_config.py`, Alembic setup.

### Phase B: DB Layer (T006–T012)
ORM models, session context manager, repositories (CRUD + search queries), Alembic migration Revision 001 (canonical DDL), Revision 002 (legacy typo convergence).

### Phase C: Service Layer (T013–T016)
`paper_service.py` (search_by_title, search_by_author, add_paper, update_field, delete_paper), `import_service.py` (extract_papers_from_tex_bib).

### Phase D: CLI Layer (T017–T025)
`prompts.py`, Typer app + top-level menu, `search` / `add` / `update` / `delete` / `import` / `migrate` subcommands.

### Phase E: Test Suite (T026–T035)
Fixtures, conftest, integration tests (repositories, services, migrations), CLI tests (CliRunner), unit tests (config, prompts), benchmark harness, doc-currency gate, coverage gate.

### Phase F: Architecture Doc & Cleanup (T036–T040)
`docs/architecture.md` reverse-engineered description, remove legacy `paper_sorts/` flat modules, update `README.md` and `CLAUDE.md`, final quality gate run.
